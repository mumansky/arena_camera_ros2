# Trigger Mode with Polarized Cameras

## Overview

This document describes how to use trigger mode with polarized cameras in the Arena Camera ROS2 driver. This feature was validated as part of **Task 7** from `ENGINEERING_TASKS.md`.

## What is Trigger Mode?

Trigger mode allows you to capture images on-demand rather than continuously streaming. This is useful for:
- Synchronized capture with external events
- Controlled frame capture for processing-intensive applications
- Reducing bandwidth and processing load

## Polarized Camera Support

The Arena Camera driver supports polarized cameras that provide 4 polarization angles:
- **0°** - Horizontal polarization
- **45°** - Diagonal polarization
- **90°** - Vertical polarization  
- **135°** - Diagonal polarization

Additionally, a **max-combined** image is generated by taking the element-wise maximum of all 4 channels, which can help highlight features visible in any polarization angle.

## Configuration

### Enable Trigger Mode

To enable trigger mode, set the `trigger_mode` parameter to `true` in your configuration file or command line:

**In `camera.yaml`:**
```yaml
/**:
  ros__parameters:
    trigger_mode: true
    pixelformat: "polarized_angles_0d_45d_90d_135d_bayer_rg8"
    publish_raw: true
    publish_compressed: true
```

**Command line:**
```bash
ros2 run arena_camera_node start --ros-args -p trigger_mode:=true -p pixelformat:="polarized_angles_0d_45d_90d_135d_bayer_rg8"
```

### Important Configuration Notes

1. **Pixel Format**: Ensure the pixel format is set to `polarized_angles_0d_45d_90d_135d_bayer_rg8` for polarized cameras
2. **Publishing Options**: You can enable `publish_raw`, `publish_compressed`, or both
3. **Exposure Time**: Set an appropriate exposure time for your use case (e.g., `exposure_time: 5000.0` for 5ms)

## Usage

### Start the Node in Trigger Mode

```bash
ros2 run arena_camera_node start --ros-args \
  -p trigger_mode:=true \
  -p pixelformat:="polarized_angles_0d_45d_90d_135d_bayer_rg8" \
  -p exposure_time:=5000.0
```

### Trigger Image Capture

Use the `trigger_image` client to capture an image:

```bash
ros2 run arena_camera_node trigger_image
```

Or use the service directly:

```bash
ros2 service call /arena_camera_node/trigger_image std_srvs/srv/Trigger
```

### Expected Behavior

When you trigger an image with a polarized camera, the following topics will publish new messages:

1. **Main Image** (original polarized format)
   - `/arena_camera_node/images` (raw)
   - `/arena_camera_node/images/compressed` (compressed)

2. **Polarization Channels** (converted to BGR8)
   - `/arena_camera_node/pol_0deg` (raw)
   - `/arena_camera_node/pol_0deg/compressed` (compressed)
   - `/arena_camera_node/pol_45deg` (raw)
   - `/arena_camera_node/pol_45deg/compressed` (compressed)
   - `/arena_camera_node/pol_90deg` (raw)
   - `/arena_camera_node/pol_90deg/compressed` (compressed)
   - `/arena_camera_node/pol_135deg` (raw)
   - `/arena_camera_node/pol_135deg/compressed` (compressed)

3. **Max-Combined Image** (element-wise maximum of all 4 channels)
   - `/arena_camera_node/pol_max` (raw)
   - `/arena_camera_node/pol_max/compressed` (compressed)

All images from a single trigger will have the **same frame ID** and **timestamp**, ensuring they are synchronized.

## Verifying Functionality

### Check Available Topics

```bash
ros2 topic list
```

You should see all the polarization topics listed above.

### Monitor Image Publishing

```bash
# Monitor main image topic
ros2 topic echo /arena_camera_node/images --once

# Monitor polarization channels
ros2 topic echo /arena_camera_node/pol_0deg --once
ros2 topic echo /arena_camera_node/pol_45deg --once
ros2 topic echo /arena_camera_node/pol_90deg --once
ros2 topic echo /arena_camera_node/pol_135deg --once

# Monitor max-combined image
ros2 topic echo /arena_camera_node/pol_max --once
```

### Verify Frame IDs Match

All images from the same trigger should have matching frame IDs:

```bash
# In one terminal, trigger an image
ros2 run arena_camera_node trigger_image

# In other terminals, check frame IDs
ros2 topic echo /arena_camera_node/images --once | grep frame_id
ros2 topic echo /arena_camera_node/pol_0deg --once | grep frame_id
ros2 topic echo /arena_camera_node/pol_max --once | grep frame_id
```

## Example Use Cases

### 1. Synchronized Multi-Angle Capture

Capture all polarization angles simultaneously for object detection or material analysis:

```bash
# Start node in trigger mode
ros2 run arena_camera_node start --ros-args -p trigger_mode:=true

# Trigger when ready
ros2 run arena_camera_node trigger_image
```

### 2. External Event Synchronization

Integrate with external systems by calling the trigger service from your application:

```python
import rclpy
from rclpy.node import Node
from std_srvs.srv import Trigger

class ExternalTrigger(Node):
    def __init__(self):
        super().__init__('external_trigger')
        self.client = self.create_client(Trigger, '/arena_camera_node/trigger_image')
        
    def capture_on_event(self):
        request = Trigger.Request()
        future = self.client.call_async(request)
        # Process response
        rclpy.spin_until_future_complete(self, future)
        return future.result()
```

### 3. Reduced Bandwidth Mode

Use trigger mode to capture only when needed, reducing network bandwidth and processing load compared to continuous streaming.

## Troubleshooting

### No Images Published After Trigger

1. **Check trigger mode is enabled**: Verify `trigger_mode: true` in config
2. **Check camera is connected**: `ros2 topic list` should show camera topics
3. **Check service availability**: `ros2 service list | grep trigger_image`
4. **Check logs**: Look for errors in node output

### Some Polarization Channels Missing

1. **Verify pixel format**: Must be `polarized_angles_0d_45d_90d_135d_bayer_rg8`
2. **Check publish flags**: Ensure `publish_raw: true` or `publish_compressed: true`
3. **Check camera capability**: Verify camera supports polarized format

### Frame IDs Don't Match

This should not occur after Task 7 implementation. If it does:
1. Check that you're using the latest version of the driver
2. Report as a bug with detailed logs

## Technical Details

### Implementation

The polarization channel processing is handled by the `process_and_publish_polarization_channels_()` function, which:

1. Checks if the image format is polarized (pixel format `0x8220020F`)
2. Splits the image into 4 channels using `Arena::ImageFactory::SplitChannels()`
3. Converts each channel from Bayer format to BGR8 (`0x02180015`)
4. Publishes each channel to its respective topic
5. Generates the max-combined image using OpenCV's `cv::max()`
6. Properly cleans up all Arena SDK image objects

This function is called by both:
- `publish_one_image_()` - for continuous acquisition mode
- `publish_an_image_on_trigger_()` - for trigger mode

This ensures consistent behavior regardless of acquisition mode.

### Pixel Format Details

- **Polarized Format**: `0x8220020F` (PFNC: `polarized_angles_0d_45d_90d_135d_bayer_rg8`)
- **Converted Format**: `0x02180015` (PFNC: `BGR8`)

### Performance Considerations

Processing polarization channels involves:
- Splitting 1 polarized image into 4 channels
- Converting 4 channels from Bayer to BGR8
- Optional JPEG compression for each channel
- Generating max-combined image (4 channels)

Total processing: 8-9 image conversions per trigger. On typical hardware, this completes in 10-50ms depending on resolution and CPU.
